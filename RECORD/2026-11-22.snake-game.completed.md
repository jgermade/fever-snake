# Snake game, first version

## 2026-11-22

- Request: a snake game whose scenario changes every few apples (3D cube,
  maze inside a tube, Windows 95 look, and more). Must be a web app on
  GitHub Pages; service workers suggested.
- Decisions:
  - Plain static ES modules, no bundler; three.js r170 vendored in `vendor/`
    so the site works offline and has no CDN dependency.
  - The snake only knows a topology interface (`key`, `step`, `isReverse`,
    `sameDir`, `cells`). Worlds supply `mapAction` (input → direction) and an
    optional `afterStep` hook to keep camera-relative control frames.
  - Cube cells use doubled integer coordinates + normal; crossing an edge makes
    the old direction the new normal. Camera "up" is rotated by the same 90°
    rotation so arrow keys stay screen-relative.
  - Tube = wrapping grid rendered on the inside of a torus (`TorusGeometry`
    parametrisation is reused for cell positions).
  - A world change keeps the snake length; the snake restarts as one cell at
    the spawn and unrolls (no need to fit a long body into a new map).
  - 5 apples per world; after world 8 it loops with an ~12% faster tick.
  - UI text in English per repository rules.
  - Service worker: versioned precache, cache-first; workflow stamps the cache
    name with the commit SHA. Not registered on localhost unless `?sw`.
- Verified: `npm test` (topologies, snake rules, SW asset list) and a headless
  Chromium run that forces apples through all eight worlds with no console
  errors; screenshots reviewed at desktop and phone sizes.
- Open: Pages must be enabled with "Source: GitHub Actions"; the workflow runs
  on `main`. No WebGL fallback yet.
