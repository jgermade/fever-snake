# More worlds, random order, touch fixes, haptics

## 2026-11-22

- Requests: more worlds; random world order; held-finger steering "does not
  work" on the user's phone; a small vibration when a turn is detected.
- Held-finger steering: the live site already served the new code (checked
  `sw.js` version and `input.js`), and emulated Chrome steered fine. Likely
  causes on a real phone: (1) the cache-first service worker served the old
  build on the first load after a deploy; (2) mobile browsers may cancel
  pointer events for their own gestures (long press, pan). Fixes: touch input
  now uses native touch events with `preventDefault` (never cancelled by the
  browser), pointer events only for mouse/pen; `-webkit-touch-callout: none`,
  `contextmenu` prevented; service worker is now network-first.
  Verified with emulated Pixel 7 and iPhone 13: resting the finger 0.9 s and
  then drawing down-left-up turns three times.
- Haptics: `navigator.vibrate(12)` on every touch-detected turn (no-op on iOS
  Safari, which has no Vibration API).
- Random order: `src/order.js` shuffles a permutation per loop with
  `first` (practice) and `after` (previous loop's last world) constraints,
  rejecting orders with adjacent 3D worlds. HUD/toast show the stage number.
  Title chips no longer show numbers.
- New worlds: Spreadsheet, Portals (`PortalGridTopology`), Tiny Planet (cube
  topology rendered on a cubed sphere), Isometric Garden (rotated controls),
  Lights Out (lantern + beam via an offscreen darkness mask).
- Tests: 27 pass (order validity/variety, authored order, unique world ids,
  portal teleport). Chromium tour across all 13 worlds in random order into a
  second loop with no errors; screenshots of the new worlds reviewed.
